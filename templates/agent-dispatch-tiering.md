# 分档调度规则（并入「编排者」的指令文件）

> **目的**：让"按难度调节投入"成为编排者的**默认行为**，而不是每次都人工决定。
> **关键**：控制点必须在**派活的人**手里 —— 只写在被调用方的提示词里，等于"求它自觉"。

**先判档，再决定「谁做」与「给多少预算」。**

- **L1 直取**（答案是**一个事实 / 数字 / 名称**，且能从**一个一手源**直接读出）
  → **编排者自己做**：最多 1 次 `websearch`，用返回摘要作答即可（**≤1 轮**），**不委派**。
  ⚠️ **若必须打开网页读原文 → 改派检索子 agent**（它在子会话里读、主线只收结论）——
  避免把整页原文灌进主线上下文（**主线上下文最贵**；"≤2 次取页"是给子 agent 的额度，不是给编排者的）。
- **L2 对比**（需要 **≥2 个来源**，或要比较 / 汇总）
  → 派检索子 agent，**≤3 轮**。
- **L3 深挖**（结论性 / 争议性判断、多源交叉、要成体系）
  → 派检索子 agent，**≤5 轮 + 1 轮证伪**。

**派活时，任务 `prompt` 的第一行必须写明档位与预算**，例：

```
档位=L2：≤3 轮；先加载 search-playbook。
问题：……
输出：结论 + 来源链接 + 置信度（直证/推断/未证）。
```

**规则**

- **判不准 → 按 L1 起步**；要升档必须写一句理由。
- 任务里**只给**「问题 + 档位预算 + 输出格式」，**不要写背景故事**。
  ⚠️ 例外：**若 L1 自己做后发现不够、要升级** → 把**已找到的线索 / URL** 一并给它
  （那是**证据**不是背景故事），避免它从头重搜、重复付费。
- 收到结果后核对：它自称的档位 / 轮次与实际是否相符；**超轮就下次收紧**。
- 执行端应有同名硬规则兜底（见 `agent-append.example.md`）。

---

## 为什么这样设计

| 常见做法 | 问题 | 本方案 |
|---|---|---|
| 所有问题都派给检索 agent | 简单问题也付重装流程 → 慢、贵 | L1 **不委派**，编排者一步搞定 |
| 指望 agent 自己"看着办" | 它天然倾向"更全面" | **派活时就把预算写死** |
| 编排者亲自抓网页 | 整页原文污染最贵的上下文 | 取页**隔离到子会话** |
| 没有观测点 | 无法知道有没有失控 | **首行自报档位 + 轮次** → 违约可见 |

> 降本不靠"求它少做"，靠**难度分级路由** + **可核账的预算**。
