# 日常检索手册

> **来源**：2026-09 一个真实检索密集型项目（数百次实战：CNKI / 万方 / 维普 / PubMed / 政府站 / 专利库 / 学术出版社 / AI 工具官网 / 互联网档案馆）的总结，并经 @librarian 独立校订（v2）。
> **目的**：提高日常信息检索「找到 + 找对」的概率。
> **怎么用**：先读 §0；可直接粘贴的纪律在 §9.2；贴墙版在 §11。

---

## 0. 总纲

**正确率 = 选对源 × 构造对查询 × 读对证据 × 及时止损**

大多数人只练第 2 项（堆关键词）。真正拉开差距的是 **第 1 项（选源）** 和 **第 3 项（读证据）**：
- 源选错 → 再好的检索式也白费
- 证据读错 → 找对了也会推出错结论

## 1. 选源：先想「答案长在哪种页面上」

### 1.1 按问题类型定源

| 你要找 | 答案通常在 | 别去 |
|---|---|---|
| 某平台有哪些功能/菜单 | 该平台**帮助中心 / 官网 / 更新日志** | 搜索引擎摘要、博客 |
| 某年发文量 / 项目数 / 记录数 | 数据库**结果页或接口 / 导出**（筛选生效后） | 二手统计、新闻；**页面显示的条数**（有上限） |
| 某规定第几条写了什么 | **官方法规库原文 / 公告 / PDF** | 解读文章、百科 |
| 某机构/产品的官方名称 | **官网 / 登记机构** | 媒体转述 |
| **统计数据 / 年鉴** | **国家统计局 `data.stats.gov.cn`、部委数据平台、世界银行/IMF/OECD** | 任何搜索引擎的二手引用 |
| **文献元数据 / DOI** | **Crossref、OpenAlex、Semantic Scholar**（免费、可批量、带引用与摘要） | 二手综述 |
| **某篇论文的免费全文** | **Unpaywall、CORE、DOAJ、预印本（arXiv/SSRN/bioRxiv）** | 绕订阅墙 |
| 某概念/原理是什么 | 教科书 / 综述 / 官方文档 | （这一步才轮到搜索引擎） |
| 某图表的原始出处 | 反向图片搜索 → 回到原文 | 二手转载 |

### 1.2 信息源权威性分层（同题优先取上层）
1. **原始/一手**：官方公告、标准原文、数据库结果页、政府网站、原始论文 PDF
2. **权威机构整理**：行业协会、大学、图书馆、**官方帮助文档**
3. **专业媒体/期刊**：有编辑与署名
4. 一般媒体 / 博客 / 问答 / UGC
5. 聚合站 / 百科 / AI 摘要（**只能当线索**）

> 口诀：**这个页面是「产生」信息的，还是「转述」信息的？**

### 1.3 AI 时代的检索纪律（重要）
搜索引擎顶部现在会给 AI 摘要。**把它当"线索"，不当"证据"**：
- AI 摘要会**自信地说错**，且不总给可核验出处
- 正确用法：**用 AI 摘要定位方向/关键词 → 回到一手页面证实**
- 想只看链接：切到「**网页/Web 视图**」（各引擎路径随版本变化，常要经「更多/工具」进入；不行就换 Bing 或 DuckDuckGo）

### 1.4 一手 > 二手
同一个数字，PDF 原文有日期和口径，新闻转述里前提已经丢了。

### 1.5 「搜不到」≠「不存在」（负证据）
找不到时要能说清：「我查了 A/B/C 三个源、用了 X/Y 两种写法，都没有」。
**负证据也要有据** —— 否则你只是"没找到"。

## 2. 通用搜索引擎：检索式怎么构造

### 2.1 五步构造法
1. **写出你要的答案"长什么样"**（一句话 / 一个数字 / 一个条款号 / 一个名字）
2. **抽 2–4 个不可替代的关键词**（术语，别丢整句）
3. **加算子收窄**（`"短语"` / `site:` / `filetype:` / `intitle:`）
4. **跑 2–3 个变体**（术语变体、中/英、精确/模糊）
5. **"借词"再搜一轮**（提升命中最快的一招）：
   先搜一次 → 打开最佳的那个一手页面 → **抄它页面上的术语**（导航/面包屑/标题/API 文档锚点里的**官方叫法**）→ 用这些词再搜一轮。

### 2.2 算子现状表（2026-09 核验）

**可靠可用**

| 算子 | 作用 | 备注 |
|---|---|---|
| `"精确短语"` | 严格按序匹配 | 最有用，还能挡掉同义噪音 |
| `site:域名` | 限定在某站 | 最可靠；可替代烂站内搜索（**百度也支持，但精度低，只当粗筛**） |
| `filetype:pdf` | 限定文件类型 | 直奔原始文件。`ext:` 是 Bing/DDG 系写法，在 Google 等价性不稳 → **Google 用 `filetype:`** |
| `intitle:词` | 词在**标题** | **单个词**可靠；`allintitle:` 可多词，但两者别混用 |
| `inurl:词` | 词在**网址** | 同上；跨引擎稳定性略差 |
| `intext:词` | 词在**正文** | 排除标题/URL 干扰 |
| `-词` | 排除 | **减号前要有空格**，且**减号与词之间不能有空格** |
| `OR` | 任一命中 | **必须大写**（小写 `or` 会被当普通词）；百度可用 `|` |
| `after:` / `before:` | 时间过滤 | **Google 官方支持**，可组合；百度较弱→用高级搜索面板 |
| `*` | 通配 | 可占**一个或多个**词（数目不定），常需配合引号；**百度不支持** |

**未官方化 / 已停用 —— 谨慎或别用**

| 算子 | 状态 |
|---|---|
| `cache:` | **已移除（2024）**；官方建议改用第三方存档（Google 结果中也出现过 Wayback 入口，随地区/版本变化） |
| `related:` | **2023-07 移除**（官方确认"效果已不好"） |
| `link:` | **2017 起不可靠**（未停用，但返回严重不全）→ 别用于链接分析 |
| `info:` | 2017 起停用 |
| `..`（数字范围） | 能用，但**长期不在官方帮助里** → 当"需自测"而非保证 |
| `~`（同义词）、`phonebook:` 等 | 早已失效 |

> 找旧网页 → 用 **Wayback Machine（archive.org）**，别指望 `cache:`。

### 2.3 三大引擎差异（实用要点）

| | Google | Bing | 百度 |
|---|---|---|---|
| `site:` / `filetype:` / `"..."` / `-` | ✅ 最稳 | ✅ | ✅（`site:` 精度低，只当粗筛） |
| `before:` / `after:` | ✅（官方支持） | ✅ | 弱 → 用高级搜索面板 |
| `*` 通配 | ✅（词数不定） | ✅ | ❌ 不支持 |
| AI 摘要 | 顶部 AI Overview，可切网页视图 | Copilot 摘要 | 顶部 AI 摘要 |
| 中文长尾 / 本土站 | 一般 | 一般 | **通常更好** |
| 英文技术 / 学术 | **通常更好** | 较好 | 较差 |

**百度特有的两个高价值技巧**
- `《书名/文件名》` —— 书名号内的内容**不被分词**、字面保留 → 找长标题/文号极有用
- `+词` —— 强制包含该词（可用性随版本变化，建议自测）

> 实操：**中文本土信息用百度兜底；英文技术/学术用 Google；不确定就三个都跑同一检索式**，比较谁先命中一手源。

## 3. 专业库不是搜索引擎（语法要单独学）

### 3.1 CNKI（知网）
- **一框式 vs 高级检索**：一框式输入框里**手写** `主题=xxx` 这类前缀会被当普通字符（结果为空/错乱）；要精确控制，请用**高级检索 / 专业检索** —— 官方支持字段码：
  `SU`(主题) `TI`(篇名) `KY`(关键词) `AB`(摘要) `FT`(全文) `AU`(作者) `AF`(机构) `JN`(刊名)
  布尔：`*` = AND，`+` = OR，`-` = NOT；用 `()` 分组。
  例：`SU='人工智能'*'教育'`
  （检索框有**字符上限**，约 120 字符）
  - **口径陷阱（重要）**：CNKI 的「**主题**」= 篇名 + 关键词 + 摘要 的**合成字段** → 用它计数和用「篇名」计数**不可比**。做计数任务必须先明确字段。（计数方法详见 §5「计数确证配方」）
- **筛选面板（facet）多为异步懒加载**：初次加载时 facet 数字可能是空/占位，**点开或等它加载完**才是真值。用程序抓页时尤其容易漏。
- **结果数 / 计数**：详见 §5「计数确证配方」。

### 3.2 万方
- **有专业检索入口**：支持字段码 + `AND/OR/NOT` 布尔（**具体字段码字母各馆/各版本不一，以官网帮助或馆内手册为准，建议实测后记录你自己的可用写法**）。
- **前缀叠加会产生"假空"**：普通输入框里同时写多个字段前缀，可能被当字面量 → 返回"无结果"（**假空**，不是真的没有）。→ 用高级检索界面，或在**单一字段**里写。
- 期刊页有「篇均被引次数」等现成指标，比自算可靠。

### 3.3 维普
- 有**稳定的字段检索体系**（题名 / 关键词 / 作者 / 机构 / 刊名 / 年份 等），**以官网帮助页为准**（别照搬 CNKI）。
  建议：进「高级检索」逐字段填写；若用表达式，**先测通再写死**（版本间有差异）。
- 部分入口反爬较强，必要时换入口/换时间/换网络再试。

### 3.4 PubMed
- **字段标签**（方括号内，可缩写）：
  `[ti]` 标题、`[tiab]` 标题+摘要、`[au]` 作者、`[ta]` 期刊、**机构/地址**（全称 `[Affiliation]`，缩写 `[ad]`，示例 `UCLA[ad]`）、`[dp]` 出版日期、`[pt]` 出版类型、`[mh]`/`[majr]` MeSH 主题词
- **做计数/集合运算用「History（检索历史）」**：PubMed 的 History 面板能保存检索式编号并用 `#1 AND #2` 组合 → 这是做计数与逐步收窄的**正确工具**，比反复改输入框可靠。
- **MeSH 的坑（重要）**：用 `[mh]` 只能命中**被标引过的**文献；**新 MeSH 词不会回溯标引旧文献** → 会漏早期文献。
  → 正确做法：**MeSH 词 `OR` 自由词**（`("neoplasm"[mh] OR tumor[tiab])`）。
- 结果数在结果页明确给出，适合计数。

### 3.5 Google Scholar
- **可靠算子**：`author:`（作者）。**注意**：`source:` / `case:` / `citedby:` **未官方文档化** → 见附录 B。
- **「合并重复版本」开关**会显著影响计数 → 做计数前先决定开/关。
- **注意**：Scholar **不走 Google 的索引**，也**不支持 `site:` / `filetype:`**。
  → 想限定域名/类型，请回到普通 Google 用 `site:`；想在 Scholar 内限定作者，直接写 `author:`。
- 「引用次数」≠ 质量；预印本/版本差异要核对。

### 3.6 专利 / 标准
- **入口**：Google Patents、Lens.org、Espacenet、CNIPA（国家知识产权局公布公告）、incoPat/佰腾等。
- **计数的正确轴线是结构化字段**：**CPC/IPC 分类号 + 同族（family）+ 法律状态 + 公开/申请日** —— 只用关键词计数会因措辞差异大幅偏差。
- 标准找**现行版本 + 发布日期**；旧版/被替代版必须标注。

### 3.7 法律法规 / 政策
- **中文一手入口**（可直接粘贴）：
  - **国家法律法规数据库 `flk.npc.gov.cn`**
  - 国务院政策文件库、司法部/各部委「规范性文件」专栏
- 注意**施行日期**与**是否已修订/废止**；媒体解读只能当线索。

## 4. 历史版本与快照

- **Wayback Machine 只按 URL 检索**（**没有**"按标题搜"）：
  - 日历视图：`web.archive.org/web/<URL>`
  - 全部快照：`web.archive.org/web/*/<URL>`
  - 指定时间戳：`web.archive.org/web/<YYYYMMDDhhmmss>/<URL>`
  - 是否存在：`archive.org/wayback/available?url=<URL>`（API）
  - 批量/元数据：**CDX API**
- 用途：页面改版 / 内容删除 / 产品下线后，**找回当时的原文**。
- 纪律：引用历史快照**必须标注快照日期** ——「当时的说法」≠「现在成立」。

## 5. 读证据：正确率的另一半

1. **结论必须能指到 URL + 一段原文**。区分"页面这么说"和"我认为"。
2. **边界值必须实测**：当结论接近某个临界值（如"超过 70""不超过 50"）时，必须拿到**实测**数字，不能以"大约""接近"替代。
3. **关于"权威单源优先"的边界**：
   - 一般性事实：**口径一致的单权威源可采信**
   - **关键数字 / 有争议的结论性断言**：仍需**第二方核对口径**（不是核对"数字是否相同"，而是核对"统计口径是否相同"）
4. **同页数字冲突**：一页里多处数字不一致很常见（正文 vs 页脚 vs 旧新闻稿）→ **取带日期与口径的那一处**；能找 **PDF/打印版**就找（能去掉异步组件带来的错漏）。
5. **计数确证配方**（别拿页面显示条数当总数）：① **导出**题录/记录数 ② 找**接口返回的 `total`** ③ **分片求和**（分年 / 分类 / 分页）④ **换入口二次核对** → 并**记录"总数来自哪一层"**。
6. **多源不一致是常态**。正确策略不是"多源一致才采信"（会大量误判），而是 **权威单源 + 只对疑点复核**。
7. **记录证据链**：`URL + 抓取时间 + 关键片段`。边查边记「结论 / 依据 / 时间」。
8. **区分「信息没有」和「我没找到」**：前者要有检索记录支撑。
9. **数字必带口径**：谁统计、什么范围、什么时候。

## 6. 止损与降级

1. **同一源试 2–3 次不中就换**（换源、换写法、换语言），别硬磕。
2. **识别「此路不通」并准备替代**：

   | 信号 | 含义 | 对策 |
   |---|---|---|
   | 403 / 验证码 / 滑块 | 反爬 | 换入口/镜像、放慢频率、换网络（后两者需人操作） |
   | 要求登录 / 机构订阅 | 权限墙 | 找**免费合法替代**（官方公开页、开放获取、预印本、图书馆订阅入口） |
   | DNS 解析失败 | 域名停用/入口迁移 | 去找**新的真实入口**（常常换了域名） |
   | **源码里没有正文（只有空壳），渲染后才出现** | **JS 渲染** | 用能执行 JS 的工具，或直接调它的接口 |
   | 源码有内容但页面空白 | 多半是 CSS/脚本报错 | 直接读源码（换浏览器/无痕模式需人操作） |

3. **并行检索**：多源同时开，谁先给答案用谁；**但要记录来源**。
4. **不重试同一 URL**：失败即走 **§6 的降级路由**；别让一次卡点拖垮整条链路。

### 6.5 合规边界（必须遵守）
- **不得绕过付费墙 / 登录墙**；不得使用盗版渠道获取文献。
- 遵守目标站的 **robots.txt 与服务条款**；控制抓取频率，不做压力式批量请求。
- 引用遵守**版权与署名**要求；对外发布时用官方/授权来源。

## 7. 反例：常见错误做法 vs 更好做法

| # | ❌ 常见错误 | ✅ 更好做法 |
|---|---|---|
| 1 | 拿 AI 摘要 / 百科当结论 | 当线索，回一手源证实 |
| 2 | 用"我以为的叫法"搜 | 先找**官方名**，再搜 |
| 3 | 把整句问题丢进搜索框 | 抽 2–4 个术语 + 算子 |
| 4 | 在输入框写了条件就以为生效 | 用筛选器/高级检索，**确认真的生效** |
| 5 | 看到一个数字就采纳 | 看**日期 + 口径 + 来源** |
| 6 | 多源不一致就全标存疑 | 权威单源优先，只复核疑点（关键数字要核口径） |
| 7 | 找不到就说"不存在" | 记录检索过程，给**负证据** |
| 8 | 死磕一个打不开的站 | 2–3 次不中就换源/换路 |
| 9 | 用 `cache:` 找旧页面 | 用 **Wayback** |
| 10 | 不记来源，回头想不起来 | 边查边记「结论/依据/时间」 |
| 11 | **拿"第 1 页显示 N 条"或筛选器数字当总数** | 计数方法详见 §5「计数确证配方」 |
| 12 | 到处搜"某论文 PDF" | 先 **Unpaywall/CORE/DOAJ/预印本**（合法且快） |
| 13 | **grep / 搜索摘要里扫到一行就下结论** | 回读命中处的**上下文**，确认该句真的支撑结论 |
| 14 | 关键结论不搜反例 | 花 1 轮搜：`<结论关键词> (deprecated OR 不再 OR 变更 OR 废止 OR 已修复)` |

## 8. 查询模板库

```
【找某平台功能/菜单的官方名】
site:<平台域名> 帮助 OR 文档 OR FAQ <功能词>
site:<平台域名> "菜单名"

【找机构/产品的官方名称与变体】
"<疑似全称>" OR "<缩写>" OR "<英文名>" site:<官网或登记机构>

【找某人/某机构的官方身份】
"<姓名>" <机构> ("教授" OR "研究员" OR "PhD") site:.edu OR site:.ac.cn

【找统计数据 / 计数】
site:data.stats.gov.cn <指标> <年份>
<世界银行/IMF/OECD> <指标> <国家> <年份>
<库内> <条件逐条列全> → 看结果页/接口的「共 N 条」（注意显示上限）

【找原文条款 / 政策】
"<关键词>" filetype:pdf site:gov.cn
<法规名> 第X条 site:flk.npc.gov.cn

【找文献元数据 / DOI（批量、可溯源）】
<标题> site:crossref.org  OR  site:openalex.org  OR  site:semanticscholar.org
DOI:<10.xxxx/xxxxx>

【找免费全文（合法）】
<标题> site:unpaywall.org  OR  site:core.ac.uk  OR  site:doaj.org
<标题> site:arxiv.org

【找历史版本 / 已删内容】（Wayback 只认 URL）
web.archive.org/web/*/<原URL>
archive.org/wayback/available?url=<原URL>
（找"变更历史"用：）site:<域名> (更新 OR 变更日志 OR changelog OR "release notes")

【找专家 / 论文】（注意：Scholar 不支持 site: / filetype:）
author:"<姓名>" <主题>            ← 在 Scholar 站内搜
<主题> filetype:pdf after:2022     ← 在普通 Google 搜

【找图片/图表的原始出处】
(先反向图片搜索) → 定位疑似原文 → site:<原文站> "<图注关键词>"

【排除干扰】
<主题> -<无关词> -<另一个无关词>     ← 减号前要有空格

【找某功能的限制/参数】
site:<平台域名> <功能词> limitations OR 限制 OR 参数
```

## 9. 落地执行

### 9.1 五步工作流
1. **定性**：我要的是**事实 / 数字 / 原文 / 名称**？→ 决定去哪类源
2. **定源**：按 §1.1 选 1–2 个权威源（+1 个兜底）
3. **构造**：按 §2.1 五步法写检索式，跑 2–3 个变体
4. **取证**：命中后**回读原文**，记 `URL + 时间 + 片段`；数字看日期/口径
5. **收口**：能证就下结论；不能证就说「未证 + 我查了什么」

### 9.2 可粘贴的检索纪律（直接复制给检索任务）
```
【检索纪律】
1. 先想"答案在哪种页面"，再去搜；能直达源站就不走搜索引擎。
2. 一手 > 二手；AI 摘要/百科只当线索，必须回原文证实。
3. 检索式 = 2-4 个术语 + 算子（"短语" / site: / filetype: / intitle:）；跑变体。
4. 筛选条件要确认"真的生效"；计数看接口/导出，别拿页面显示的条数当总数。
5. 每个结论都要能指到 URL + 原文片段；数字必看日期与口径。
6. 权威单源可采信；关键数字与争议性断言必须第二方核对口径；多源不一致是常态。
7. 同一源 2-3 次不中就换路；负证据也要有检索记录。
8. 边查边记：结论 / 依据(URL) / 时间。
9. 已移除的算子别用（cache:/related:/info:）；link: 不可靠；找旧页面用 Wayback（只按 URL）。
10. 引用旧快照必须标注日期；文献优先走 Unpaywall/CORE/DOAJ/预印本，不绕付费墙。
```

## 11. 贴墙速记

> **先想"答案在哪种页面"，再去搜。**
> **一手 > 二手；源站 > 搜索引擎；AI 摘要只当线索。**
> **命中率最快的一招：打开最佳页面，抄它页面上的"官方术语"再搜一轮。**
> **`"短语"` + `site:` + `filetype:` 是英文/技术场景的三件套；中文场景换成 `"短语"` + `site:` + 百度高级搜索面板。**
> **筛选要真生效；计数别信页面上限；数字看日期与口径。**
> **权威单源优先；关键数字再核口径。**
> **2–3 次不中就换路；负证据也要有据。**
> **边查边记：结论 / 依据 / 时间。**
> **`cache:` / `related:` / `info:` 已废；`link:` 不可靠；旧页面用 Wayback（只按 URL）。**

## 附录 B · 存疑 / 需注意

- **算子行为会变**（Google 近两年改动尤其频繁）→ 建议**每隔几个月复核一次**；本表以 **2026-09** 为准。
- 存疑项（**未完全确认，使用前建议自测**）：
  1. `cache:` 的**准确停用日期**（2024-08 公告 / 2024-09 报道，两说）
  2. `ext:` 在 Google 当前是否仍生效（非官方文档化，SEO 圈说法矛盾）
  3. Bing 对 `intext:` / `inurl:` 的支持程度（未实测）
  4. **万方 / 维普当前版本的具体字段码字母**（各馆手册版本不一 → **建议实测后再写死**）
  5. CNKI 接口 `data.totals`、万方"前缀叠加假空"来自**实战一手经验**（可复现），但**官方未文档化**，换版本可能失效
  6. **Google Scholar 的 `source:` / `case:` / `citedby:` 未官方文档化**（`citedby:` 通常只是结果页链接，不是可输入算子）→ 用前自测；`-` 排除是否支持亦未核实
  7. 百度 `+词` 强制包含的可用性（随版本变化）
  8. **`-site:` 在 Google 是"实际可用"还是被官方明确排除**（本次未定论；本手册按"可用"处理，仅采纳"减号前需空格"）
  9. **执行阈值**（并发 ≤4 页 / 单 URL 1 次 / 同域名连败 2 次 / 深挖 ≤5 轮）是**经验值**，需按实际预算校准，写死可能误事
  10. **时效复核阈值 N**（默认 6 个月）**无实证依据** —— 建议在真实任务里统计一次误判率后再定
- **百度**的 `before:`/`after:` 支持较弱 → 用高级搜索面板。
- **Google 搜索结果中的 Wayback 入口**随地区/版本变化，不要当成必有功能。
